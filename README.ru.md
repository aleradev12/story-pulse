# Story Pulse

[English](README.md) | **Русский**

Story Pulse — pre-MVP Telegram-бота для коллективного детектива. Игроки предлагают идеи, задают вопросы по опубликованным уликам и выдвигают обвинения. OpenAI-совместимый API Сбера помогает модерировать и группировать идеи, писать следующую главу и готовить финальную разгадку.

> Это ранний прототип для контролируемых тестов. Сейчас он работает одним процессом Node.js, хранит состояние в локальном JSON-файле и использует long polling Telegram.

## Основной цикл продукта

1. Администратор открывает раунд командой `/open`.
2. Игроки читают текущую главу и отправляют текстовую идею или выбирают быстрый вариант. Бот оценивает вклад и возвращает персональную «теневую ветку», но не обещает включить идею в канон.
3. Игроки задают вопросы по уликам через `/ask` и смотрят общий список улик командой `/clues`.
4. Администратор закрывает раунд командой `/close`. Модель группирует принятые идеи, объясняет влияние сообщества и пишет следующую главу.
5. После настроенного количества раундов отдельный вызов модели фиксирует разгадку. Игроки отправляют финальные обвинения командой `/accuse`, администратор публикует разгадку через `/finish`.

Текущая история находится в [`story.json`](story.json). Шаблоны промптов вынесены в [`src/prompts.json`](src/prompts.json), а сборка сообщений и канона — в `src/prompts.js`.

## Требования

- Node.js 20.6 или новее
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)
- Числовой Telegram ID администратора
- Выданные вашей команде доступы к AI API Сбера: API-ключ, Base URL и ID модели из ответа `GET /models`

Не коммитьте `.env`, API-ключи, токены Telegram и `data/state.json`.

## Настройка и запуск

```sh
npm install
cp .env.example .env
```

Заполните `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=...
SBER_API_KEY=...
ADMIN_TELEGRAM_ID=...
SBER_BASE_URL=... # точный Base URL, выданный Sber500
SBER_MODEL=...    # ID модели из ответа GET /models
```

Приложение вызывает `{SBER_BASE_URL}/chat/completions`, передавая Bearer-токен и формат JSON. Укажите Base URL и модель, полученные от сервиса; приложение не подставляет выдуманные значения.

```sh
npm run check
npm start
```

`npm start` использует поддержку `--env-file=.env` в Node.js. Храните файл `.env` в секрете. По умолчанию `AUTO_SCHEDULE` выключен — для ручного теста используйте команды администратора. Расписание можно включить через `AUTO_SCHEDULE=true` и настроить `OPEN_HOUR`, `REMINDER_HOUR`, `CLOSE_HOUR`, `TIME_ZONE`.

## Команды Telegram

### Игроки

- `/start` — присоединиться к тесту
- `/story` — показать текущую главу и варианты
- Обычный текст — отправить идею в открытом раунде
- `/ask <вопрос>` — задать вопрос по расследованию
- `/clues` — показать опубликованные улики
- `/accuse <подозреваемый> — <обоснование>` — отправить финальное обвинение, когда оно доступно
- `/help` — краткая справка

### Администратор

Команды доступны пользователю с ID из `ADMIN_TELEGRAM_ID`:

- `/open` и `/close` — открыть/закрыть раунд
- `/status` — посмотреть числа участия и состояние истории
- `/broadcast <текст>` — отправить сообщение активным участникам
- `/finish` — опубликовать финальную разгадку
- `/reset CONFIRM` — сбросить прогресс истории, сохранив записи участников

## Архитектура

```text
Пользователи Telegram
       │ Telegram Bot API (long polling)
       ▼
src/index.js ─────── src/prompts.js ─────── src/prompts.json
       │                        │
       │                        └── подстановка канона и данных в шаблоны сообщений
       ├── src/llm.js ───────── API Сбера, совместимый с OpenAI /chat/completions
       ├── story.json ───────── мир, персонажи, начальная глава и улики
       └── data/state.json ──── участники, состояние раундов, идеи, улики и история
```

Бот работает одним процессом. `src/store.js` загружает историю и сохраняет полное состояние в `data/state.json` через временный файл и атомарное переименование. Такое JSON-хранилище подходит только для небольшого прототипа, а не для конкурентной записи или горизонтального масштабирования. Для сетевых сбоев LLM-клиент использует ограниченное число повторных попыток. Логи сейчас выводятся в stdout/stderr процесса; постоянные структурированные логи, метрики, DAU и экспорт пока не реализованы.

## Развёртывание

Бот использует long polling Telegram, поэтому ему не нужен входящий публичный HTTP endpoint или webhook. Однако процесс должен постоянно работать на хосте с доступом в интернет — например, на VPS или в managed container platform, а не на localhost разработчика. Передавайте переменные окружения через хранилище секретов хостинга, сохраняйте каталог `data/`, настройте перезапуск при сбое и ограничьте доступ к данным и логам. Не публикуйте `.env` или `data/state.json`.

В репозитории пока нет манифеста развёртывания или конфигурации для хостинга. Перед публичным запуском добавьте мониторинг доступности, резервное копирование, надёжное хранилище, управление секретами, структурированные логи и метрики, ограничение частоты запросов и правила хранения персональных данных.

## Проверки и дальнейшая работа по масштабированию

`npm run check` проверяет синтаксис JavaScript. В репозитории **нет** отчёта о нагрузочном тестировании и подтверждённых результатов для 10 RPS, TPM/TPS или стресс-тестов. Эти показатели нужно измерять на развёрнутом сервисе с выданным API Сбера; синтаксическая проверка не является нагрузочным тестом.

Следующий минимальный шаг — собирать DAU, частоту взаимодействий по типам, задержки и токены/стоимость LLM-запросов, ошибки сервисов. Для выгрузки подойдут JSON Lines или CSV с минимизированными идентификаторами и определённым сроком хранения. Не записывайте по умолчанию исходный пользовательский контент и секреты.

### Стоимость LLM на одного активного пользователя в день

Оценку нужно строить на фактических ценах провайдера и измеренном потреблении:

```text
стоимость на DAU в день = Σ(входные токены × цена входа + выходные токены × цена выхода)
                           по среднему числу запросов пользователя за день
```

Измеряйте токены промпта и ответа для каждого этапа продуктового цикла (модерация идеи, вопрос, закрытие раунда, финальная разгадка), затем умножайте на ожидаемую частоту действий. Генерация изображений пока не реализована. Цены и доступные модели задаются вне этого репозитория и могут меняться.

## Приватность и ограничения

- Файл состояния содержит Telegram ID, имена, идеи и вопросы. Считайте его персональными данными и не публикуйте.
- Одна история и один процесс; JSON-файл не подходит для большой нагрузки и нескольких реплик.
- Только текст: голос, изображения и PDF не поддерживаются.
- Метрики работы сервиса, дашборды, результаты нагрузочных тестов и автоматическое развёртывание пока не добавлены.
- Автоматическая модерация не заменяет контроль администратора.
